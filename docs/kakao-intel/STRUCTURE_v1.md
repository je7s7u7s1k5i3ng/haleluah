## 2. M0. 시장신호 수집기 `kakao_intel` (기술 파이프라인)

목적: 단톡방을 **"3~6개월 앞선 수요 신호"** 데이터로 쓴다 (부록 C §5b). 기존 `news_collector.py`와 같은 저장소에 둔다.

| 단계 | 처리 | 산출물 |
|---|---|---|
| 1. 파싱 | `[닉네임] [오전/오후 h:mm] 본문` + 날짜 헤더 → 메시지 레코드 | `messages` 테이블 |
| 2. 마스킹 | 닉네임 → 해시, 전화·계좌·이메일 정규식 제거 | 원문 Notion 복제 금지 |
| 3. 중복 제거 | 파일 해시 + (시각, 화자해시, 본문해시) | 같은 방 재export 대응 |
| 4. 분류 | 키워드 사전으로 카테고리 태깅 (AI·쇼츠·쇼핑쇼츠·전자책·블로그·공구 …) | `tags` |
| 5. 집계 | 월별 카테고리 비율, 신규 급등어(전월 대비 ×3), 게시자 수 | `trends.json` |
| 6. 리포트 | 월 1회 신호 요약 → 사람 검토 후 Notion 기록 | `signal_report_YYYYMM.md` |

스키마 (SQLite):
```sql
messages(id, room_id, ts, speaker_hash, body_masked, has_link, link_domain, input_hash)
tags(message_id, category)
rooms(room_id, title, first_ts, last_ts, source_file_hash)
```
`run_id`, `input_hash`, `output_hash`는 v3.0 §5·§8 필드를 따른다.

## 3. M1. 공구·공지 엔진 (→ 쇼핑몰 주문통합 v2.0) — **1순위**

근거: 부록 B. 오늘(10/19) 기준 **딸기 첫 출하 공지 시즌(11~12월)이 임박**해서 가장 먼저 적용한다.

### 3.1 공지 템플릿 5종 (`templates/notice/*.md`)

| ID | 유형 | 필수 슬롯 |
|---|---|---|
| N1 | 오픈 공지 | 날짜헤더 / 오늘 추천 3줄 / 스펙카드 / 주문마감 시각 / 링크 1개 |
| N2 | 게릴라·마감임박 | `[게릴라]` / N박스 한정 / 정가→행사가 / 마감 시각 / 링크 1개 |
| N3 | 품절·종료 | "○분 만에 종료" + 다음 회차 예고 (품절을 다음 홍보로) |
| N4 | 배송 안내 | 3줄 고정: 발주마감 / 발송마감 / 재개일 |
| N5 | 신상품·첫수확 | `[오늘부터 수확 시작]` + 한 줄 희소성 + 스펙카드 |

**스펙 카드 (모든 공지·상세페이지 첫 블록 고정)**
```
★상품명★  ○○딸기 (품종) 특/상
판매가    ○○,○00원   (배송비 포함 / 별도 ○,○00원)
구성      500g×2 / 1kg / 2kg     합포장 ○개
당도      ○○brix (측정일)        출고  오전 ○시 주문분 당일 출고
```
규칙: 글 1개 = 상품 1개 = 링크 1개. 가격 끝자리 ○,500 / ○,900.

### 3.2 운영 리듬 (`channels.json` → `publish_schedule`)
- 정기 슬롯: 화·수·목 **11:00** (공지) + **20:00~22:00** (하루 요약글)
- 주문 마감 고정 시각 1개 선택 후 모든 공지에 표기 (예: 익일 09:00)
- 주말 게시는 평일의 절반 이하

### 3.3 딸기 시즌 캘린더 (2026-11 ~ 2027-06)
| 시기 | 액션 | 템플릿 |
|---|---|---|
| 11월 중 | 첫 출하 공지 + 중량 사다리 (가정용/선물용 고급박스) | N5 |
| 12월 | 연말 선물세트, 수요 투표("50명 모이면 오픈") | N1 + 투표 |
| 1월 (설 D-10) | 발송 마감 3줄 공지 | N4 |
| 2월 (피크) | 수량 한정 게릴라 → 종료 공지 반복 | N2 → N3 |
| 6~10월 비시즌 | 냉동딸기·잼·제휴 과일로 알림 유지 | N1 |

### 3.4 CS 문구 세트 (`templates/cs/*.md`)
지연 / 품절 후 접수 / 맛 보장 범위("맛 환불 O, 모양·크기 X") / 연휴 / 택배파업·기상 / 주문 폭주(순차발송 vs 취소 선택권 + 보상쿠폰). 발송은 `SEND` 권한.

### 3.5 플랫폼 정지 방지 규칙 (QA 게이트에 추가)
부록 B: 비교 대상 판매자가 **가송장 입력 + 판매자 일방 취소 누적으로 스마트스토어 영구 정지**(2024-11).
- `QA_BLOCK`: 실제 집화 전 송장 입력 금지 / 고객 동의 없는 취소 금지
- 예약 상품은 기상 리스크 사전 고지 문구 필수
- 백업 주문 경로 (카톡채널 주문서 양식) 유지 — 단, 고객 원문은 SQLite 원장에만, Notion·로그에는 마스킹

## 8. Gemini 설계 병합 자리 (대기)

Gemini 공유 대화 본문을 받으면 여기서 위 M0~M4와 대조한다.
- 겹치는 항목 → 기존 모듈에 통합 (새 문서 생성 금지)
- 새 항목 → 모듈 추가 또는 우선순위 재조정
- 충돌 항목 → 기준점 2026-07-11 문서 우선, 차이를 변경 이력에 기록
