# 로컬 작업 지시서 — 스크롤 수집 검증 + 수정 설계도 (2026-10-31)

> 이 파일은 **사장님 PC(Jesusisgood)에서 도는 Claude Code 또는 Codex**가 그대로 실행하는 작업 지시서다.
> 클라우드 세션은 Windows PC의 J:·K:·노트북에 접근할 수 없어서 이 방식으로 넘긴다.
> 사용법: 이 파일을 `J:\프로그램 관리\원격 컴퓨터 제어\` 에 넣고, PC의 Claude Code에 아래 한 줄을 붙여넣는다.
>
> ```
> J:\프로그램 관리\원격 컴퓨터 제어\LOCAL_TASK_scroll_verify.md 를 읽고 그대로 수행해. 끝나면 [작업 완료 검증] 표로 보고해.
> ```

## 0. 지켜야 할 규칙 (사장님 운영 패턴)

1. **자동으로 진행**하되, 성공 판정에는 **실제 결과물과 증거**(파일 경로, 개수, 해시, 출력 원문)를 붙인다. 확인하지 않은 것을 완료라고 하지 않는다.
2. **읽기 전용 검증이 먼저**다. 수집 프로그램, 데이터 파일, 예약작업은 **수정·삭제·재시작하지 않는다**. 고칠 곳은 설계도에만 쓴다(사장님 승인 후 반영).
3. **작동하던 파일과 성공 패턴은 보존**한다. 덮어쓰지 말고 새 판본 파일로 쓴다.
4. 측정 실패나 미확인은 **빈칸·HOLD**로 남긴다. 성공으로도 실패로도 바꾸지 않는다.
5. 기록에 이미 있는 답을 다시 묻지 않는다. 같은 교정을 반복하지 않는다.
6. 창을 띄워 사장님 작업을 방해하지 않는다. 작업 위치는 `J:\프로그램 관리\원격 컴퓨터 제어\` 로만 한다.
7. 구글·네이버 차단을 **IP 순환이나 캡차 풀기로 우회하는 수정안은 쓰지 않는다**(약관 위반, 계정·회선 차단 위험). 대안은 냉각, 서킷 브레이커, 공식 API.
8. 막히면 멈추지 않는다. 그 단계를 `HOLD(사유)`로 적고 다음 단계로 간다.

## 2. 결과 데이터 검증 (읽기 전용)

### 2-1 전체 스캔
```
python "J:\프로그램 관리\원격 컴퓨터 제어\tools\scan_scroll_data.py" "K:\스크롤 데이터" > "J:\프로그램 관리\원격 컴퓨터 제어\검증\scan_report_20261031.json"

### 2-2 판정표 (scan_report 값으로 채운다)

| # | 항목 | 정상 기준 | scan_report 키 | 판정 |
|---|---|---|---|---|

| V2 | 빠진 날 | 운영 기간 중 공백일 0 (의도적 휴무일 제외) | `day_gaps` | |
| V3 | 깨진 파일 | 0 | `broken_count` | |
| V4 | 빈 파일 | 0 | `empty_files_count` | |
| V5 | 중간에 끊긴 파일 | `.tmp/.part` 0 | `temp_leftovers_count` | |
| V6 | 파일 중복 | 0 | `dup_groups` | |

### 2-3 표본 확인 (숫자만 보지 않기)
- 가장 최근 파일 3개, 가장 작은 파일 3개, 중복 의심 1쌍을 열어서 실제 내용이 **정상 수집 결과인지**, **차단·로그인·빈 결과 화면이 저장된 것인지** 확인한다.
- 원문을 보고서에 복사하지 말고 "정상 / 차단화면 / 빈결과 / 깨짐" 판정과 파일 경로만 적는다.
