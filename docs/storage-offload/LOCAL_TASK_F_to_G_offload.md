# LOCAL_TASK — F:\채널 별 롱폼 숏폼 원본 → G드라이브 이동 (용량 확보)

상태: CANDIDATE (v1.2.0 · 클라우드 테스트 25개 통과 · 실제 F: 실행 전)
안티그래비티용 지시문: `docs/storage-offload/ANTIGRAVITY_지시문_F_to_G.md`
작성: 2026-11-11

## 0. 확인된 사실
- 이번 세션 기록과 G드라이브 검색 결과, **'F 원본 → G드라이브 이동' 규칙이나 프로그램은 없었습니다.**
  있는 것은 `01_MANDATORY_J_WORKSPACE_ZERO_RESIDUE_CONSTITUTION.md`(J: 작업 흔적 0, 결과물은 목적지 폴더로 이동)뿐입니다.
  그래서 F에 원본이 그대로 쌓였습니다. 옮기는 프로그램이 없었고, 클라우드 세션은 F:에 접근할 수 없습니다.
- 이 프로그램이 그 빈자리를 채웁니다. 기본은 미리보기이고, 확인 후 실행합니다.

## 1. 남기는 것 / 옮기는 것
| 구분 | 처리 |
|---|---|
| 성공 패턴 기록 (.md .json .txt .py 등) | **안 옮김.** 각 폴더에 그대로 |
| 20MB 미만 (썸네일 이미지 등) | 안 옮김 |
| 유튜브에 올린 최종 영상 (경로에 최종·완성·업로드·final·upload) | 안 옮김. `--include-finals`을 붙일 때만 옮김 |
| 프로그램(J:\프로그램 관리, I:\자동화 프로그램)의 .py·.json·.bat 등이 경로로 가리키는 파일·폴더 | 안 옮김 |
| 최근 14일 안에 고친 파일 · `작업중.lock` 등이 있는 폴더 | 안 옮김 |
| 그 외 큰 원본 (촬영 원본·중간 렌더·소스 영상·음성·압축본) | **G드라이브로 이동** |

옮기는 순서: G드라이브에 복사 → 크기 + SHA-256 일치 확인 → F 원본 삭제. 불일치면 원본을 남기고 실패로 기록합니다.

## 2. F:에 남는 위치 안내
- `F:\채널 별 롱폼 숏폼\00_원본은_G드라이브에_있음.txt` — 어디서 찾는지 사람용 안내
- `F:\채널 별 롱폼 숏폼\00_G드라이브_이동위치.json` — 전체 위치표 (상대경로 → G 경로·크기·SHA-256·이동시각)
- 옮긴 파일이 있던 폴더마다 `_G드라이브에_있음.txt` — 그 폴더 파일들의 G 위치
- G 쪽 구조는 같습니다. `F:\채널 별 롱폼 숏폼\X\Y.mp4`는 `G:\내 드라이브\보관_원본\채널 별 롱폼 숏폼\X\Y.mp4`에 있습니다.

## 3. PC 클로드 코드에 한 줄 지시
```
haleluah 저장소 claude/busy-ramanujan-pgcgfo 브랜치의 storage_offload 폴더를 J:\프로그램 관리\원본 G드라이브 이동 에 받아서, docs/storage-offload/LOCAL_TASK_F_to_G_offload.md 4번 순서대로 미리보기 → 결과 보고 → 내 승인 후 실행까지 해줘
```

## 4. 실행 순서 (PC)
1. `G:\내 드라이브`가 열리는지, 구글 드라이브 앱이 **스트리밍** 모드인지 확인합니다. 미러링이면 G의 파일이 로컬 디스크에도 남습니다.
2. `1_미리보기.bat` — 옮길 개수·용량, 건너뛴 이유별 개수, 프로그램 참조로 보호된 경로가 나옵니다. 아무것도 옮기지 않습니다.
3. 미리보기 결과를 사장님께 보고하고 승인을 받습니다.
4. `2_실행_G드라이브로_옮기기.bat` — 용량 제한 없이 대상 전체(약 400GB도 가능)를 옮깁니다.
   단, 구글 드라이브 앱은 G:에 넣은 파일을 클라우드에 다 올릴 때까지 **캐시 폴더(기본 C:)** 에 임시로 들고 있습니다.
   그래서 파일마다 C: 여유를 재고, 20GB 아래로 내려가면 `상태: 캐시대기`로 멈춥니다 (못 옮긴 파일은 F에 그대로).
5. `캐시대기`면 업로드가 진행되어 C: 여유가 돌아온 뒤 4번을 다시 실행합니다. `대상 0개`가 될 때까지 반복합니다.
   구글 드라이브 설정에서 캐시 위치를 F:로 바꿨다면 `--cache-drive F:\` 로 실행합니다.
6. 검증: `00_G드라이브_이동위치.json`의 `마지막실행.실패`가 비었는지 확인하고, 임의 3개를 `--find`로 찾아 G에서 열리는지 확인합니다.

## 5. 찾기 · 되돌리기
```
python offload_to_gdrive.py --find "파일이름 일부"
python offload_to_gdrive.py --restore "경제/20261001_롱폼/원본클립.mp4"
```
되돌릴 때도 SHA-256을 다시 비교합니다.

## 6. 미확인 (HOLD)
- F:\채널 별 롱폼 숏폼의 실제 용량과 폴더 구조 — 미리보기 결과로 확인
- '성공 패턴이 각 폴더에 심겨 있다'는 점은 클라우드에서 보지 못했습니다. 그래서 문서·설정·작은 파일은 아예 옮기지 않게 만들었습니다.
- 최종본 판정은 이름 규칙 기반입니다. 이름에 '최종' 같은 표시가 없는 업로드본은 미리보기 목록에서 확인해야 합니다.
