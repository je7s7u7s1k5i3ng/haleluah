# 안티그래비티 지시문 — F:\채널 별 롱폼 숏폼 원본 → G드라이브 이동 (약 400GB 확보)

상태: CANDIDATE (프로그램 v1.2.0 · 클라우드 테스트 25개 통과 · 실제 PC 실행 전)
작성: 2026-11-11

아래 `===== 지시문 시작 =====` ~ `===== 지시문 끝 =====` 을 통째로 안티그래비티 에이전트 창에 붙여 넣으면 됩니다.

---

===== 지시문 시작 =====

너는 사장님 PC(Windows)에서 F 드라이브 용량을 확보하는 작업을 한다.
목표: `F:\채널 별 롱폼 숏폼` 안에서 **유튜브에 올린 최종 영상을 뺀 큰 원본 파일(촬영 원본·중간 렌더·소스 영상·음성·압축본)** 을
`G:\내 드라이브\보관_원본\채널 별 롱폼 숏폼\` 의 **같은 하위 경로**로 옮기고, F에는 어디로 옮겼는지 위치 표시 파일을 남긴다.
예상 대상 용량은 약 400GB다.

## 절대 규칙
1. 이동은 반드시 `offload_to_gdrive.py`(v1.2.0)로만 한다. 탐색기 잘라내기, robocopy /MOV, 직접 짠 스크립트로 옮기지 않는다.
   이 프로그램은 G에 복사 → 크기 + SHA-256 일치 확인 → 그때만 F 원본 삭제, 그리고 위치표 기록까지 한다.
2. 아래는 F에 그대로 남긴다 (프로그램이 자동으로 거른다. 규칙을 바꾸지 말 것):
   - .md .json .txt .py 등 문서·설정 = 각 폴더에 심어 둔 성공 패턴 기록
   - 20MB 미만 파일 (썸네일 등)
   - 경로나 이름에 최종 / 완성 / 업로드 / final / upload 가 들어간 최종 업로드본
   - J:\프로그램 관리, I:\자동화 프로그램 의 코드·설정이 경로로 가리키는 파일
   - 최근 14일 안에 고친 파일, `작업중.lock` / `00_작업중` / `_보관금지` 가 있는 폴더
3. 옵션을 임의로 바꾸지 않는다 (`--include-finals`, `--최소MB`, `--최근일` 등). 바꿔야 할 이유가 보이면 멈추고 사장님께 묻는다.
4. "완료"는 증거(아래 6단계 검증 결과)로만 말한다. 검증 못 한 항목은 HOLD로 보고한다.
5. 작업 파일과 로그는 `J:\프로그램 관리\원본 G드라이브 이동\` 에만 둔다. 다른 곳에 임시 파일을 만들지 않는다.

## 1단계 — 프로그램 준비
1. 폴더 `J:\프로그램 관리\원본 G드라이브 이동\` 을 만든다 (있으면 그대로 쓴다).
2. `G:\내 드라이브\원격 컴퓨터 제어_전달_20261031\offload_to_gdrive.py` 를 그 폴더로 복사한다.
   - 그 위치에 없으면 G드라이브에서 `offload_to_gdrive.py` 를 검색한다.
   - 그래도 없으면 GitHub 저장소 haleluah 의 `claude/busy-ramanujan-pgcgfo` 브랜치 `storage_offload/offload_to_gdrive.py` 를 받는다.
3. 확인: 그 폴더에서 `python offload_to_gdrive.py --help` 를 실행했을 때 `--cache-drive` 와 `--list-file` 옵션이 보여야 v1.2.0이다.
   안 보이면 옛 파일이다. 멈추고 보고한다.

## 2단계 — 사전 점검 (결과를 표로 기록)
| 항목 | 확인 방법 | 기준 |
|---|---|---|
| G드라이브 연결 | `G:\내 드라이브` 폴더가 열리는지 | 열려야 진행 |
| 구글 드라이브 앱 모드 | 트레이 아이콘 → 톱니 → 설정 → Google Drive | **스트리밍**이어야 함. 미러링이면 멈추고 사장님께 보고 (미러링이면 옮긴 파일이 로컬 디스크에도 남는다) |
| 캐시 위치 | 같은 설정 화면의 '로컬 캐시 파일 디렉터리' | 기본은 C:. F:로 바꿔 두었으면 3·4단계에 `--cache-drive F:\` 를 붙인다 |
| C: 여유 | `Get-PSDrive C` | 기록만. 60GB 미만이면 "캐시 위치를 F:로 바꾸면 더 빨리 끝난다"고 사장님께 알린다 |
| F: 여유 (전) | `Get-PSDrive F` | 기록 (나중에 비교) |
| 구글 드라이브 남은 저장공간 | drive.google.com 저장용량 또는 앱 설정 | 옮길 용량보다 커야 함. 부족하면 멈추고 보고 |

왜 C:가 나오나: 구글 드라이브 앱은 G:에 넣은 파일을 클라우드에 다 올릴 때까지 캐시 폴더(기본 C:)에 임시로 들고 있다.
그래서 F→G 이동 중에는 C: 공간이 잠깐 줄고, 업로드가 끝나면 돌아온다. 프로그램은 파일마다 캐시 드라이브 여유를 재고,
20GB 아래로 내려가면 그 회차를 스스로 멈춘다 (`상태: 캐시대기`). 못 옮긴 파일은 F에 그대로 있다.

## 3단계 — 미리보기 (아무것도 안 옮김)
```
cd /d "J:\프로그램 관리\원본 G드라이브 이동"
python offload_to_gdrive.py --list-file "J:\프로그램 관리\원본 G드라이브 이동\이동예정_목록.txt"
```
사장님께 보고할 것:
- 옮길 개수, 용량(GB), 건너뛴 이유별 개수 (작은 파일·문서 / 최종 업로드본 / 프로그램이 참조 / 최근 수정 / 작업중 표시 폴더)
- 프로그램이 참조해서 보호된 경로 예시
- `이동예정_목록.txt` 에서 **이름에 '최종' 표시는 없지만 유튜브 업로드본으로 보이는 파일**을 골라 따로 표시
  (예: 폴더 안 영상이 하나뿐인 경우, 파일명이 유튜브 제목과 같은 경우). 이런 파일이 있으면 그 폴더에 `_보관금지` 빈 파일을 만들지 사장님께 묻는다.
- 용량이 400GB와 크게 다르면 (예: 100GB 미만) 이유를 건너뜀 개수에서 찾아 같이 보고한다.

**사장님이 "실행"이라고 답하기 전에는 4단계로 가지 않는다.**

## 4단계 — 실행
```
python offload_to_gdrive.py --execute
```
(캐시를 F:로 옮겼다면 `python offload_to_gdrive.py --execute --cache-drive F:\`)
- 출력 마지막 JSON의 `상태` 를 본다.
  - `완료`: 5단계 생략, 6단계로
  - `캐시대기`: 5단계로
  - `일부실패`: `실패` 목록의 이유를 보고한다. "검증 불일치"는 원본이 F에 남아 있으니 다음 실행 때 다시 시도된다. 같은 파일이 2번 연속 실패하면 멈추고 보고한다.
  - `HOLD`: 이유(원본 폴더 없음 / G드라이브 없음)를 보고하고 멈춘다.
- 출력은 `J:\프로그램 관리\원본 G드라이브 이동\실행로그_YYYYMMDD_HHMM.txt` 에 그대로 저장한다.

## 5단계 — 캐시대기면 기다렸다가 반복
1. 10분마다 캐시 드라이브 여유를 잰다 (`Get-PSDrive C`, 캐시를 옮겼으면 F).
2. 여유가 50GB 이상 돌아오면 4단계를 다시 실행한다.
3. 미리보기에서 `대상 0개` 가 될 때까지 반복한다. 회차마다 옮긴 개수·GB를 누적 기록한다.
4. 2시간 동안 여유가 전혀 늘지 않으면 업로드가 멈춘 것이다. 구글 드라이브 앱 상태(일시중지 / 오류 / 로그아웃)를 확인하고 보고한다.
   임의로 앱을 재설치하거나 캐시 폴더를 지우지 않는다.
참고: 400GB 업로드 시간은 인터넷 업로드 속도에 따라 다르다 (100Mbps 기준 대략 9~10시간). PC를 끄지 않게 사장님께 알린다.

## 6단계 — 검증 (이게 있어야 '완료')
1. `F:\채널 별 롱폼 숏폼\00_G드라이브_이동위치.json` 이 있고, `파일` 개수가 누적 옮긴 개수와 같다.
2. 같은 JSON의 `마지막실행.실패` 가 비어 있다.
3. 무작위 3개를 찾아 G에서 열리는지 확인한다:
   `python offload_to_gdrive.py --find "파일이름 일부"` → 나온 G 경로의 파일을 열어 재생되는지 본다.
4. `F:\채널 별 롱폼 숏폼\00_원본은_G드라이브에_있음.txt` 가 있고, 옮긴 파일이 있던 폴더마다 `_G드라이브에_있음.txt` 가 있다.
5. 구글 드라이브 앱 트레이 아이콘이 '동기화 완료' 상태다 (업로드 대기 0).
6. F: 여유 (후) − F: 여유 (전) ≈ 누적 확보GB.
7. G 쪽에 `.part` 로 끝나는 파일이 남아 있지 않다.

## 7단계 — 최종 보고 형식
```
[F→G 이동 보고]
상태: 완료 / 진행중(캐시대기 n회차) / HOLD(이유)
옮긴 파일: n개 · nnn.nGB   (회차별: 1회 …, 2회 …)
F: 여유 전 → 후: …GB → …GB
남긴 것: 문서·작은 파일 n개, 최종 업로드본 n개, 프로그램 참조 n개, 최근 수정 n개, 작업중 폴더 n개
실패: 없음 / 목록
검증 1~7: 각 항목 통과·미확인
위치표: F:\채널 별 롱폼 숏폼\00_G드라이브_이동위치.json
로그: J:\프로그램 관리\원본 G드라이브 이동\실행로그_….txt
```

## 나중에 파일이 필요할 때
- 찾기: `python offload_to_gdrive.py --find "파일이름 일부"` → G드라이브 경로가 나온다.
- 되돌리기: `python offload_to_gdrive.py --restore "경제/20261001_롱폼/원본클립.mp4"` → F 원래 자리로 복사하고 SHA-256을 다시 비교한다.
- 사람이 직접 찾을 때: F의 같은 폴더에 있는 `_G드라이브에_있음.txt` 를 열면 그 폴더 파일들의 G 위치가 적혀 있다.
