## 3. "터지는 주제" 수집에 필요한 구조 (보강 설계)

### 3.1 신호 — 숫자로 잴 수 있는 것만 (공식 경로 우선)
| 신호 | 출처 | 무엇을 재나 |
|---|---|---|
| S1 검색량 급상승 | 네이버 데이터랩 검색어 트렌드 API (공식) | 최근 7일 vs 이전 28일 평균 비율 |
| S2 영상 인기 급상승 | YouTube Data API `videos.list?chart=mostPopular&regionCode=KR` (공식) | 게시 후 시간당 조회수(속도) |
| S3 동시 보도 | 구글 뉴스 RSS(한국판 `gl=KR&ceid=KR:ko`) + 언론사 RSS | 최근 6시간 동안 같은 사건을 다룬 **매체 수** |
| S4 보도량 급증 | S3 누적 | 키워드별 시간당 기사 수 vs 지난 7일 같은 시간대 평균 (z-점수) |
| S5 채널 적합도 | 채널별 키워드 사전 (건강·경제·역사·맛가득·기독교) | 우리 채널과 맞는 정도 |

화면 긁기로 순위표를 가져오는 방식(포털 실시간 순위 등)은 넣지 않는다. 막히면 원격 제어 설계도 §6의 냉각·서킷 브레이커를 쓴다.

### 3.2 처리 순서
```
수집(S1~S4) → 원문 링크 풀기·제목에서 언론사 꼬리 떼기 → 같은 사건 묶기(제목 유사도)
→ 주제별 점수 계산 → 이전 회차 대비 신규/상승/하락 표시 → 상위 N개만 보고서
```

### 3.3 점수 (시작값, 운영하며 튜닝)
```
터짐점수 = 0.30·S4(보도 급증 z) + 0.25·S3(동시 보도 매체 수 정규화)
        + 0.25·S1(검색 급상승 비율) + 0.20·S2(영상 조회 속도)
채널점수 = 터짐점수 × S5(채널 적합도)
```
- 각 신호를 못 가져오면 0이 아니라 **빈칸(HOLD)**으로 두고, 나머지 가중치로 다시 나눈다 (측정 실패를 낮은 점수로 둔갑시키지 않음).
- 보고서의 "조회수/반응 지표" 칸에는 **이 숫자들만** 쓴다. 문장 추정 금지.

### 3.4 저장
- 중복 제거 키(원문 URL·사건 묶음 ID)는 **파일/SQLite에 저장**해 재시작 후에도 유지.
- 회차마다 manifest(수집 시각, 신호별 성공·실패, 기사 수, 주제 수).
- 신선도 규칙: 발행 48시간 초과 기사는 "터지는 주제" 근거에서 제외(참고 자료로만).

### 3.5 검증 (성공 판정)
- 기술 성공: 신호 4종 중 3종 이상 수집, 회차 manifest 정상.
- 콘텐츠 성공: 상위 주제로 만든 영상·글의 실제 성과를 다음 회차에 역주입.
- **"점수 9/10"류 주관 점수로 SUCCESS 승격 금지.**
