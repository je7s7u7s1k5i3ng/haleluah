## 2. 원인 → 수정 설계

### 2.1 입력 (F1)
| 현재(추정) | 수정 |
|---|---|
| 키 입력 흉내로 긴 한/영 혼합 문장을 타이핑 | **클립보드 붙여넣기**로 바꾼다 (클립보드에 넣고 Ctrl+V). 한/영 전환 영향 없음 |
| 줄바꿈을 ` \| `로 바꿔 한 줄로 입력 | 붙여넣기는 줄바꿈 그대로 가능. Enter 전송 대신 **전송 버튼 클릭** |
| 입력 후 바로 전송 | **입력창 내용을 다시 읽어 원문과 비교**(글자 수 + 해시). 다르면 전송하지 않고 지우고 재시도 1회 → 실패 시 `INPUT_CORRUPT`로 격리 |
| 6~7천 자 한 번에 | 소스별 길이 상한(예: 1,500자) + 총량 상한. 넘으면 요약본 사용 또는 **노트북LM 소스 업로드**로 분리 |

### 2.2 대화 묶기 (F3)
- 클러스터마다 **새 채팅**에서 시작한다.
- 프롬프트 첫 줄에 실행 표식 `[RUN:<클러스터>-<run_id 8자>]`을 넣고, "답변 첫 줄에 이 표식을 그대로 적어라"를 요구한다.
- 캡처한 응답 첫 줄에 같은 표식이 없으면 `WRONG_THREAD` → 저장하지 않는다.

### 2.3 캡처 (F5)
- 화면 전체 텍스트가 아니라 **마지막 응답 영역(요소)만** 읽는다.
- 생성이 끝났는지(중지 버튼 사라짐 + 2초간 글자 수 변화 없음) 확인한 뒤 읽는다.
- 사이드바·안내문 문구 목록으로 2차 청소.

### 2.4 검증 관문 — 저장 전에 반드시 통과 (F2·F4·F7)
`pattern_tuning/argon_gate.py` (이번에 추가, 테스트 4개 통과, 실제 #18 보고서로 FAIL 확인):

| 코드 | 판정 | 내용 |
|---|---|---|
| G1_INPUT_CORRUPT | FAIL | 프롬프트 메아리에 한/영 뒤섞인 덩어리·기호 낀 덩어리 3개 이상 |
| G2_MODEL_ADMITS_MISSING | FAIL | 응답이 "깨짐·잘린 상태·입력 대기·붙여넣어 주시면" 등 누락을 인정 |
| G3_WRONG_THREAD / CHANNEL_MISMATCH | FAIL | 머리말 클러스터 번호·채널과 본문이 다름 |
| G4_UI_CHROME | WARN | 화면 껍데기 섞임 (청소 후 재판정) |
| G5_SECTION_MISSING / TRUNCATED_TAIL | WARN | 1·2·3 섹션 누락, 끝 잘림 |
| G6_UNGROUNDED_NUMBERS | FAIL | 입력이 망가졌는데 입력에 없던 수치 5개 이상 생성 |
| G7_SCORE_ON_FAILURE | FAIL | 실패 보고서에 기준선 점수가 찍힘 |

- **FAIL** → `07_BLACKLIST_실패`(실패 기록소)로, KB·성공 패턴·점수 계산에서 제외.
- **WARN** → 자동 청소 후 재판정, 그래도 WARN이면 사람 확인 대기.
- **PASS** → 그래도 `CANDIDATE`. 성공 승격은 실제 영상 성과로만.

### 2.5 점수 다시 정의 (F7)
고정 도장 `99.97`을 없애고 **매 회차 측정값**으로 바꾼다.
```
기술 점수 = 100 × (관문 PASS 보고서 수 / 생성 보고서 수)
보조 지표: 입력 무결(G1 통과율) · 대화 일치(G3 통과율) · 근거 수치 비율 · 섹션 완결률
성과 점수 = 이 보고서로 만든 영상의 실제 시청 지속·클릭률 (업로드 후 7일·14일)
```
- 원장(`00_성공실패_패턴강화_실시간원장.json`)에 `generated / pass / warn / fail / fail_codes / pass_rate` 칸을 추가하고, `newly_synced`는 **PASS만** 센다.
- 기술 점수와 성과 점수를 한 숫자로 합치지 않는다.

### 2.6 실패 학습 (F6)
- 같은 실패 코드가 한 회차에 3번 → 그 단계 **자동 중지** + 알림 1회(원격 제어 방어 설계도 §4 사다리 L5).
- 실패 코드별 원인·수정 이력을 실패 기록소에 남기고, 수정 전까지 같은 방식 재실행 금지.

### 2.7 모델·계정 확인 (F10)
- 프롬프트 문장 대신 **화면의 모델 라벨이 아르곤인지** 확인한 뒤 전송한다(아니면 실행하지 않음).
- "크레딧 초기화 대기" 같은 한도 표시가 보이면 그 계정은 `DEFERRED`, 리셋 시각 이후 재개.

### 2.8 중복·구성 (F8·F9)
- 같은 클러스터 재실행은 `_v2`처럼 판본을 붙이고, 관문 결과가 좋은 쪽 하나만 기준으로 지정.
- 클러스터 구성 코드에서 `슈카월드·언더스탠딩`이 항상 붙는 이유 확인 → 의도된 기준 채널이면 설계에 명시, 아니면 수정.

## 3. 소급 정리 (이미 쌓인 55건)

1. `python argon_gate.py --folder "<아르곤 보고서 폴더>" --out 판정결과_소급.json` 실행 (읽기 전용).
2. FAIL 보고서는 **삭제하지 않고** `QUARANTINED`로 표시해 실패 기록소 목록에 올린다.
3. 그 보고서를 근거로 만든 KB·기준선 항목(GEN8 등)을 `업데이트필요`로 되돌린다.
4. 원장 점수를 소급 판정 결과로 다시 계산한다.
5. 같은 클러스터를 2.1~2.3 수정 후 다시 돌려 PASS본으로 교체한다.

## 6. 하지 않은 것 (명시)

- 기존 설계 파일·코드·원장은 수정하지 않았다(접근 불가 + 작동 파일 보존 원칙).
- 55건 전부를 판정하지 않았다. 직접 읽은 것은 3건이고, 3건 모두 FAIL이다. 나머지 판정은 §3 실행 결과로 확정한다.
- "99.97점이 틀렸다"는 3건 표본 기준의 판단이다. 소급 판정 결과로 숫자를 확정한다.

## 7. 기존 설계와 병합 규칙
- 기존 설계에 같은 항목이 있으면 이 파일의 F번호를 **추가 조항**으로 붙인다.
- 충돌하면 더 엄격한 쪽(실패를 성공으로 세지 않는 쪽)을 따른다.
- 기존 설계에만 있는 항목은 그대로 둔다.
